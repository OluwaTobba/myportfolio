Backend service · Go

Monitoring and observation platform

A single-binary monitoring server (obsd) with no third-party dependencies. It scrapes Prometheus-format endpoints, accepts pushed metrics, stores time series, evaluates alert rules and serves a query API.

  • Storage is an in-memory, label-indexed time-series store with per-series caps and time-based retention.
  • Alert rules move through pending, firing and resolved states, with notifications to logs or a webhook.
  • The README documents tests for the storage engine, the Prometheus parser, the alert state machine and config validation.

A reference implementation. Data is kept in memory and is lost on restart, and the server has no authentication, so it is meant to sit behind an authenticated reverse proxy.

Engineering approach

How I approach backend work

Examples from my projects, rather than general principles.

API design

The monitoring platform separates ingestion (a JSON write endpoint) from reads: a query endpoint with optional bucketed downsampling, plus series, alerts and targets endpoints for inspection.

Data modelling

Series are indexed by their label sets. The store applies a per-series cap and time-based retention, so old and excess samples are dropped rather than held indefinitely.

Testing and failure states

Alert rules move through pending, firing and resolved states. According to its README, the project tests that state machine, the Prometheus parser and config validation.

Security and deployment

The monitoring server documents that it has no authentication and should sit behind an authenticated proxy. My Go training project covers REST APIs, gRPC, PostgreSQL, Docker, Kubernetes and JWT authentication.
